# LLD ST-04: Sanitized sample dataset builders

## 1. Purpose

Test-only builders for the sanitized demo dataset (PyMuPDF PDFs, openpyxl EBOMs) and a typed expected-outcome manifest shared by downstream tests (story ST-04; SRS section 10; AGENTS.md Tooling). All data is invented. No production code, no `models` import (ST-04 depends on ST-01 only), no real engineering files.

Consumers named in stories: ST-10, ST-11, ST-16, ST-20, ST-21, ST-22, ST-28, ST-29, ST-30, ST-34, ST-42. Consumers of the invalid-input variants (by type, not cited): ST-06, ST-07, ST-08 (via ST-06/07), ST-13, ST-14. ST-12, ST-15, ST-17 to ST-19, ST-23 and ST-24 use their own data apart from the cases named below. Traces: ST-04 T1 to T6; SRS section 10, section 9 criteria 4 to 7; A1, A3, A4, A7.

## 2. File tree

```
tests/sample_dataset.py        # specs, manifest constants, builders
tests/conftest.py              # sample_dataset fixture (S1)
```

## 4. Dataset content and manifest (contract for downstream stories)

Component block (A3): one text box per component, lines in order `<REF>`, value, `PN: <part number>`, description. Every page also has a title block `SANITIZED SAMPLE SCHEMATIC`. Part numbers identify a family, not a value (S4), so the C201 value change is the only unintended change. Values and descriptions contain no `[A-Z]{1,3}\d+` token (e.g. `OPAMP`, not `LM358`).

| Ref | Original (page, value) | Modified | Layout-only | PN | Description |
|---|---|---|---|---|---|
| R101 | 1, 10K | 1, 4.7K | 1, 10K | PN-RES-001 | Resistor 0603 |
| R102 | 1, 1K | 1, 1K | 1, 1K | PN-RES-001 | Resistor 0603 |
| R103 | 1, 100R | absent | 2, 100R | PN-RES-001 | Resistor 0603 |
| C201 | 2, 100nF | 2, 220nF | 2, 100nF | PN-CAP-001 | Capacitor 0603 |
| C301 | absent | 2, 100nF | absent | PN-CAP-002 | Capacitor 0603 |
| U101 | 2, OPAMP | 2, OPAMP | 3, OPAMP | PN-IC-001 | Dual op-amp 8-pin |

Layout-only derives from the original components (S5), has no annotations, and is used in the "modified" role: a diff against the original is empty; page count 3 vs 2. Modified and layout-only have no annotations.

EBOM (A4): header `Reference Designator`, `Part Number`, `Description`, `Quantity`; one row per reference, quantity 1, order R101, R102, C201, C301, U101. References, part numbers and descriptions equal the modified schematic. Mismatch: C201 part number `PN-CAP-999`, R102 row removed, U101 quantity 2. Missing-column: `Quantity` header absent (3 headers).

Invalid inputs: `password.pdf` is the modified PDF encrypted (AES-256) with `PDF_USER_PASSWORD` and `PDF_OWNER_PASSWORD`. `not_a_pdf.pdf` is plain text `not a pdf` (no `%PDF` header).

Exported constants (statuses are strings equal to `models.Status` values, e.g. `Status.PASS == "Pass"`; no `models` import needed). Tuple order is not significant for consumers; compare as sets.

| Constant | Type | Value |
|---|---|---|
| `PDF_USER_PASSWORD`, `PDF_OWNER_PASSWORD` | `str` | dummy test constants, distinct |
| `ORIGINAL_COMPONENTS`, `MODIFIED_COMPONENTS`, `LAYOUT_ONLY_COMPONENTS` | `tuple[ComponentSpec, ...]` | table above, table order |
| `EBOM_MATCH_ROWS`, `EBOM_MISMATCH_ROWS` | `tuple[EbomRow, ...]` | EBOM rows above |
| `ANNOTATIONS` | `tuple[tuple[int, str], ...]` | (page 1-based, text), insertion order: (1, `Replace R101 from 10K to 4.7K`), (1, `Replace R102 from 1K to 2.2K`), (1, `Remove R103`), (2, `Add C301 100nF`), (2, `Improve filtering on input stage`); Text annotations (S7) |
| `EXPECTED_CHANGE_ITEMS` | `tuple[tuple[str, str], ...]` | (id, status): CR-001 Pass, CR-002 Fail (observed 1K), CR-003 Pass, CR-004 Pass, CR-005 Unable to Verify (unstructured) |
| `EXPECTED_UNINTENDED` | `tuple[tuple[str, str, str, str], ...]` | (ref, field, original, modified): `(("C201", "value", "100nF", "220nF"),)`; layout-only gives none |
| `EXPECTED_EBOM_ENTRY_MATCH` | `tuple[tuple[str, str], ...]` | (ref, status): R101, R102, C201, C301, U101 all Pass |
| `EXPECTED_EBOM_ENTRY_MISMATCH` | same | C201 Fail (part number), R102 Fail (absent from EBOM), R101 Pass, C301 Pass, U101 Pass |
| `EXPECTED_EBOM_QTY_MATCH` | `tuple[tuple[str, int, int, str], ...]` | (part number, schematic qty, EBOM qty, status): PN-RES-001 2/2, PN-CAP-001 1/1, PN-CAP-002 1/1, PN-IC-001 1/1, all Pass |
| `EXPECTED_EBOM_QTY_MISMATCH` | same | PN-IC-001 1/2 Fail, PN-RES-001 2/1 Fail, PN-CAP-002 1/1 Pass; PN-CAP-001 and PN-CAP-999 not asserted (S6) |
| `EXPECTED_CONNECTIVITY` | `str` | `"Unable to Verify"` (A7) |
| `EBOM_HEADERS`, `EBOM_MISSING_COLUMN` | `tuple[str, ...]`, `str` | the four headers; `"Quantity"` |

## 5. Algorithm

PDFs (`fitz`, US-ASCII text only):

1. New document; one A4 page (595 x 842) per page number in the variant.
2. Title block via `insert_textbox` at rect `(72, 30, 472, 80)`. Component `i` on a page (table order) at rect `(x0, y0, x0 + 160, y0 + 70)` with `x0 = 72 + 200 * (i % 2)`, `y0 = 100 + 100 * (i // 2)`; font `helv`, size 10. A negative `insert_textbox` return raises `AssertionError` (explicit `raise`, not `assert`).
3. Original only: for `k` = global 0-based index in `ANNOTATIONS`, add a Text annotation at point `(500, 60 + 30 * k)` with the text as content, in order.
4. Fixed metadata (empty creation and modification dates); save to `path`.
5. Password variant: build modified, save with `encryption=fitz.PDF_ENCRYPT_AES_256`, `user_pw=PDF_USER_PASSWORD`, `owner_pw=PDF_OWNER_PASSWORD`.

XLSX (`openpyxl`): one sheet, header then spec rows; `created` and `modified` set to `datetime(2026, 1, 1, 0, 0, 0)`; save. `build_dataset` calls all builders with the fixed file names.

## 6. Error and `Unable to Verify` handling

Builders write only to `path` and raise on any PyMuPDF or openpyxl error. The manifest assigns `Unable to Verify` where data is deliberately absent (descriptive annotation, connectivity); no missing data is encoded as `Pass`. Determinism is content-level (S3). Environment risk: the repo has no `pyproject.toml`, so dependencies (PyMuPDF, openpyxl) and the `tests/` import path are unverified (ST-01 scope; not fixed here).

## 8. Assumptions (all new; linked to backlog A-ids where applicable)

- S1: `conftest.py` and the shared fixture live in `tests/` and are owned by ST-04.
- S2: module imported as top-level `sample_dataset` (no package).
- S3: story "deterministic" means identical extracted content, not identical bytes (PDF IDs, zip timestamps uncontrolled).
- S4: a part number identifies a family; descriptions carry no value (A3, A4).
- S5: layout-only variant derives from the original, not the modified PDF (ST-04 T3).
- S6: ST-24 behaviour for a schematic part number absent from the EBOM (PN-CAP-001, PN-CAP-999 in the mismatch EBOM) is unspecified, so not asserted (A4).
- S7: all annotations are Text annotations, not FreeText (A1).
- S8: extra fixtures for ST-06, ST-07, ST-10, ST-13 edge cases (corrupt, empty-page, empty-content annotation, bad quantity) are built inline by those stories, outside ST-04.
- S9: replace, part-number-change and connectivity examples beyond ST-04 T1 to T6 are out of scope for this dataset.
