# LLD ST-09: Reference designator parser

## 1. Purpose

Provide `find_ref_des(text)`, a pure function that returns the reference designators found in a string, in first-occurrence order and de-duplicated (story ST-09; FR-05; assumption A2). Consumed by ST-10 (`component_ref` = first match), ST-12 and ST-15. Deterministic, no I/O, no logging (NFR-07: input may be annotation or schematic text). Size S: about 6 production LOC (cap S 30; story estimate 15).

## 2. File tree

```
extraction/ref_des.py      # find_ref_des (scaffold, signature only)
tests/test_ref_des.py      # exists (docstring only)
```

Location follows the AGENTS.md layout (`extraction/`) and architecture section 2 (extraction owns annotation and schematic text parsing). Depends on the standard library only (`re`); no shared models needed.

## 3. Public signatures

```python
def find_ref_des(text: str) -> list[str]: ...
```

## 4. Data structures

One module-level compiled pattern (case-sensitive):

```
(?<![A-Za-z0-9_])[A-Z]{1,3}[0-9]+(?![A-Za-z0-9_]|\.[0-9])
```

- `[A-Z]{1,3}[0-9]+` is A2 verbatim: 1 to 3 capital letters, then digits.
- The lookbehind/lookahead enforce token boundaries (assumption L2).
- ASCII classes only, so non-ASCII letters and digits never match.

## 5. Steps

1. If `text` is not a `str`, raise `TypeError` (assumption L5).
2. `matches = pattern.findall(text)` (left to right, non-overlapping; no capture groups, so full match strings).
3. Return `list(dict.fromkeys(matches))`: first-occurrence order, duplicates removed. No sorting, so order is stable and deterministic.

## 6. Error and `Unable to Verify` handling

- No match or empty string returns `[]`. The parser emits no status; callers map `[]` to "not extractable" and must not treat it as `Pass` (AGENTS.md rule; ST-10 T2 sets `component_ref=None`).
- Non-`str` input (including `None`) raises `TypeError`, a programming error, not a data condition (L5).
- Matching is purely lexical: a match does not prove the designator exists in any schematic or EBOM.
- Confidentiality: the function does not log; the `TypeError` message must name the type only, never echo the value.

## 7. Assumptions (new, labelled L)

| # | Assumption | Basis |
|---|---|---|
| L1 | Case-sensitive: lowercase (`r101`) does not match. | A2 says "capital letters"; conservative. |
| L2 | A match must be a whole token: not preceded or followed by `[A-Za-z0-9_]`. So `R101A`, `xR101`, `1R101`, `AB1234X`, `ABCD1` (4 letters), `R_101` give no match. `XR101` is a valid 2-letter designator and returns `XR101` (never a partial `R101`). | Conservative: avoids false designators inside part numbers and words. |
| L3 | Other punctuation and whitespace are boundaries: `R101,`, `(R101)`, `R101.`, `R101-R105`, `R101/R102`, `NET-R101` yield the designators. Non-ASCII characters adjacent to a designator are also boundaries: `R101é` and `R101١` return `["R101"]`. | Common prose and range text; no source forbids it. |
| L4 | A designator directly followed by `.` plus a digit (`R1.5`, `U101.1`, `V3.3V`) does not match, to avoid reading decimals and pin suffixes as designators. | Conservative; pin references are out of scope for ST-09. |
| L5 | Non-`str` input raises `TypeError`; empty string returns `[]`. | Fail loudly on misuse; empty is valid data. |
| L6 | Digits are ASCII `0-9`, at least one; leading zeros allowed (`R007`), `R0` matches. | A2 says "digits" without limits. |
| L7 | Ranges are not expanded: `R101-R105` returns `["R101", "R105"]` only. | Expansion is not in the story; no invented intent. |

## 10. Open questions

1. Should `U101.1`-style pin references return the component (`U101`)? L4 currently rejects them.
2. Should lowercase designators (`r101`) be supported? A2 says capitals; L1 rejects them.
3. Should ranges (`R101-R105`) be expanded? L7 says no.
4. A3 is unconfirmed against a real Zuken export; real designators may use suffixes (`R101A`) or hierarchical prefixes that L2 rejects.

## 11. Downstream notes (no change to ST-09 behaviour)

- ST-10: A2 defines no exclusions, so `find_ref_des` also matches non-component tokens such as `ECN12`, `USB2`, `LM358`, `C0603`. ST-10 taking the first match as `component_ref` can pick one of these; ST-10 must decide how to handle it.
- ST-12: T1/A3 need a whole-line single-designator check, which `find_ref_des` alone cannot give (it returns every match, not whether the line holds only one designator). ST-12 must implement that check.
