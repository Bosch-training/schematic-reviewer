# LLD ST-02: Shared data models

## 1. Purpose

Define the enums and Pydantic v2 models used by every module (architecture sections 3, 6; story ST-02). Models are declarations only: no I/O, no validators, no logic beyond field defaults. Modules import from `models` and never from each other (NFR-01).

## 2. File tree

```
models.py            # all enums and models (story scope: "one module")
tests/test_models.py
```

Both files exist as docstring-only scaffolds. Root location matches `safe_logging.py` (ST-03) and is an assumption: the AGENTS.md layout names no shared-models location (open question 1).

## 3. Public signatures

```python
class Status(str, Enum):          # "Pass", "Fail", "Unable to Verify"
class Category(str, Enum):        # "Component", "Value", "Part number", "EBOM", "Connectivity", "Unintended change"
class ChangeType(str, Enum):      # "Add", "Remove", "Replace", "Value change", "Part-number change"
class Decision(str, Enum):        # "Pending", "Approved", "Rejected", "Requires Investigation"

class Annotation(BaseModel):
    text: str
    page: int
    component_ref: str | None = None

class ChangeRequestItem(BaseModel):
    id: str
    change_type: ChangeType | None = None
    component_ref: str | None = None
    old_value: str | None = None
    new_value: str | None = None
    source_annotation: Annotation
    structured: bool = False

class Component(BaseModel):
    ref_des: str
    value: str | None = None
    part_number: str | None = None
    description: str | None = None
    page: int

class EbomEntry(BaseModel):
    ref_des: str
    part_number: str | None = None
    description: str | None = None
    quantity: int | None = None

class Finding(BaseModel):
    id: str
    change_request_ref: str | None = None
    category: Category
    schematic_ref: str | None = None
    expected: str | None = None
    observed: str | None = None
    status: Status
    severity: str | None = None                 # A6: no rules, stays None
    evidence: str | None = None
    reviewer_decision: Decision = Decision.PENDING
    reviewer_comment: str | None = None

class ReviewSession(BaseModel):
    id: str
    input_names: list[str] = Field(default_factory=list)
    change_items: list[ChangeRequestItem] = Field(default_factory=list)
    findings: list[Finding] = Field(default_factory=list)
    overall_decision: Decision = Decision.PENDING
```

Field set follows architecture section 6 plus `change_items` (story T4; omitted from the architecture diagram, needed by `PUT /reviews/{id}/changes/{item_id}`, open question 5). Types and optionality not fixed by a source are proposals.

## 4. Data structures

- Enums subclass `str`, so JSON holds the SRS wording as the value.
- Member names are upper snake case (`UNABLE_TO_VERIFY`, `PART_NUMBER_CHANGE`); values are the exact strings above.
- `Status` and `Decision` values are the SRS section 6 wording (NFR-04). `Category` uses SRS section 6 wording in sentence case. `ChangeType` is not enumerated in the SRS; values come from architecture section 4 step 3 in sentence case (open question 2).
- Lists use `Field(default_factory=list)`.
- `None` on an optional extracted field means "not extracted".
- `Finding` carries source traceability through `change_request_ref` (item id), `schematic_ref` (page and component text, SRS section 6) and `evidence`. There is no separate source-document field (open question 3).

## 5. Steps

1. Define the four enums with SRS-exact values.
2. Define `Annotation`, `Component`, `EbomEntry`.
3. Define `ChangeRequestItem` referencing `Annotation`.
4. Define `Finding`. Required: `id`, `category`, `status`. Defaults: `reviewer_decision=PENDING`, `severity=None`, `reviewer_comment=None`.
5. Define `ReviewSession` referencing `Finding` and `ChangeRequestItem`.

## 6. Error and `Unable to Verify` handling

- Unknown enum values, including wrong casing, raise `ValidationError`.
- `Status` has no default, so a missing result cannot become `Pass`.
- `EbomEntry.part_number`, `description`, `quantity` and the optional `Component` fields are `None` when absent or unparseable (ST-13 T3, architecture section 5). Consumers map `None` to `Unable to Verify`, never `Pass`. Only `ref_des` (the match key) is mandatory.
- `structured=False` marks an item the engineer must clarify; the validator, not the model, emits the `Unable to Verify` finding (architecture section 4 step 3). The model does not enforce that `structured=True` implies `change_type` is set (open question 6).
- Confidentiality (NFR-07): `ValidationError` text includes input values, which may be annotation text or EBOM data. Callers must not log or echo it; log `error_type` only (ST-03).

## 8. Open questions

3. Architecture section 4 step 2 says extraction records carry "source document and page", but the section 6 models have no source-document field, and `Component` cannot tell original from modified. Add `source_document: str` to `Annotation`, `Component`, `EbomEntry` and `Finding`, or keep separate lists per document?

5. Add `change_items` to the architecture diagram (story T4 requires it)?
6. Should `structured=True` require `change_type`? That needs a validator and extra LOC.
7. EBOM `quantity` as `int` follows ST-13 T3; confirm fractional quantities are out of scope.
8. Estimated size is about 62 production LOC against the M cap of 60 (story says 55). Accept the overshoot, or split enums from models?
